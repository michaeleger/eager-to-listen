# ADR 0001: Value-for-Value with Nostr Wallet Connect (NIP-47)

## Status
Accepted (Feature-flagged behind `FeatureFlags.V4V_NWC`; enabled in debug builds, disabled in release builds).

## Context
Podcasting 2.0 specifies the `<podcast:value>` tag for Value-for-Value (V4V) payments over the Lightning Network. Listeners stream satoshis or send one-off "boostagrams" directly to creators and splits.

Traditional Lightning integration in mobile apps requires either:
1. Running an embedded mobile Lightning node (heavy resource consumption, battery drain, channel liquidity management).
2. Holding custodial balances in-app (severe regulatory, compliance, and Google Play Store financial licensing risks).
3. Delegating entirely to external wallet apps via generic `lightning:` intent URIs.

Nostr Wallet Connect (NWC / NIP-47) provides a standardized, non-custodial remote control protocol. Users connect their existing Lightning wallet (e.g., Alby, Mutiny, Umbrel, Coinos, Voltage) via an encrypted Nostr relay connection.

## Decision
1. **NWC Protocol over OkHttp WebSocket**:
   Implement NIP-47 client using the existing OkHttp WebSocket connection pool. The client supports `pay_keysend` (with bLIP-10 TLV records) and `pay_invoice` commands.

2. **Proportional Split Calculation (`V4VSplitMath`)**:
   Implement deterministic proportional split allocation across multiple feed recipients according to their weights. Invariant: The sum of allocated satoshis must strictly equal the user's chosen amount. Integer division remainders are assigned to the primary non-fee creator.

3. **Podcasting 2.0 / bLIP-10 Metadata (`BoostagramPayload`)**:
   Format boostagram metadata (feed, episode title, GUID, timestamp, action="boost", app_name, app_version, message, sender_name, millisat values) into TLV record `7629169` as UTF-8 JSON.

4. **Keystore-Backed Secret Storage (`NwcKeyStorage`)**:
   Persist NWC connection secrets using hardware-backed AES-256-GCM encryption in Android KeyStore. Secrets are never logged or exported in plain text backups.

5. **Feature Flag Guardrails (`FeatureFlags.V4V_NWC`)**:
   Guard the NWC interface behind `FeatureFlags.V4V_NWC`. In release builds (`BuildConfig.DEBUG == false`), the feature flag evaluates to false to ensure Play Store policy compliance and security audit readiness. Release builds fall back safely to external `lightning:` URI intents.

## Consequences
- **Positive**:
  - Non-custodial: Eager to Listen never holds, routes, or transmits custody of listener funds.
  - Seamless UX: In debug builds, boosts can be sent directly without switching apps.
  - Standards-compliant: Follows Podcasting 2.0 and bLIP-10 specifications.
  - Safe Play Store rollout: Zero regulatory risk for Google Play closed testing.
- **Negative / Mitigations**:
  - Requires an active Nostr relay connection for NWC requests. Mitigated by configurable timeouts and graceful fallback to external intent URIs.
